## 真实 API 实测

使用本机已有账户的当前启用接口：智谱 `glm-4.7-flash`，未改动其密钥或配置。通过进程内 HTTPX ASGI transport 调用实际 JSON-RPC 路由，以该本地账户的临时会话执行，不涉及密码修改，不写出会话令牌。

新建工作区：`真实模型全流程验收 2026-10-30`。样本：现有 `data/cv-validation/historical/fast_rcnn.pdf`，728,919 字节，9 页，9 个原文片段。上传与 PDF 解析成功，模型处理计划分为 2 批。

首次测试返回 HTTP 401。用户重新验证并启用配置后，鉴权已恢复；再次测试第一批成功，第二批遇到 429，诊断保存在 [限流记录](live-validation-2026-10-30-rate-limit.json)。合并单批的排查发现 4096 个输出 tokens 全用于思考，没有生成正文，见 [输出预算记录](live-validation-2026-10-30-thinking-budget.json)。

**智谱专项调整后，默认两批模式的实际 API 流程已通过。** 9 页、9 个原文片段，提取约 71.18 秒，26 条指标结果成功入库；论文与指标重新查询、覆盖分析、原文证据查询及原始 PDF 逐字节一致性检查均通过。两批都由真实模型返回 JSON，无失败批次。详见 [最新实测记录](live-validation-2026-10-30.json)。成功工作区 ID：`workspace_真实模型全流程验收_2026_10_30_107ac6b7`。

另有单批排查运行保存了 14 条结果，见 [单批记录](live-validation-2026-10-30-single-batch.json)。日常默认分批参数未修改。

这验证了技术流程，不代表科研抽取质量已完成验收：模型返回的部分单位不符合领域规则，被过滤；作者、年份等元数据和方法 / 场景分类仍需人工核对。此轮未使用真实账户在浏览器逐个检查入库后的视图。

## 智谱并发优化（其他厂商不变）

- 智谱模型调用和保存 / 测试接口的模型探测共用一个进程级请求通道。多个线程与事件循环也会串行处理；不依赖单个 provider 实例的锁。
- 请求结束后保留 1 秒间隔；429 自动按 3 / 6 / 12 秒退避，最多重试三次。有 `Retry-After` 时遵守更长的等待；超过 60 秒则保留错误供稍后人工重试，不提前重发。401 不重试，取消或异常会释放通道。
- 仅对智谱 GLM-4.7 系列关闭默认思考，避免输出预算耗尽而正文为空。依据：[智谱官方思考模式说明](https://docs.z.ai/guides/capabilities/thinking-mode)。没有把思考内容当论文提取结果。
- 锁只协调同一个后端进程，无法限制用户在其他程序或独立服务器中使用同一密钥的请求；这类上游限流仍通过有限重试处理。
- 其他 API 的并发策略、请求参数和用户保存的配置不变。

可复跑：`backend\.venv\Scripts\python.exe -X utf8 -m scripts.validate_live_workflow`。每次创建新的验收工作区并实际调用当前接口，会产生模型请求。成功时继续检查预览、入库、指标、覆盖、证据及原始 PDF 字节一致性；失败时保留诊断。
