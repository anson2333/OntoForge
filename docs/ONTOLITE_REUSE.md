## 本次采用

- `frontend/src/components/LlmProfilesModal.tsx` 与 `backend/services/llm_provider.py:verify_profile`：保存前试调用，失败不写入。OntoForge 沿用自己的用户隔离和原生 Claude provider，连接验证以正常文本回复为准，不要求 JSON；论文抽取的结构化校验独立进行。

- 失败后的恢复路径：预览失败页可以直接打开模型接口设置，再重试预览；401/403 等明确错误停止后续批次，减少无效等待。

## 保留当前课程项目的要求

领域包定义指标及分类，PDF 提供论文证据，两者分开说明。不能直接把 OntoLite 的知识实体图代替本项目的指标矩阵、断言证据、候选空白及工作区权限。

OntoLite 的验证器把 HTTP 429 当成可保存，本项目要求实际请求成功才允许保存，避免限流或余额不足时被误认为已可用。扫描件识别、图表多模态和异步进度任务需要适配当前数据结构，本次没有据此宣称已移植。

## 使用顺序

进入工作区中的领域 → 配置模型接口并“验证并启用” → “上传论文 PDF” → 查看提取摘要和警告 → 确认入库 → 查看矩阵、证据与覆盖分析。

模型调用的测试使用本地 HTTP fixture；真实论文质量仍需配置有效服务后人工核查。
