# 目标检测规则：设置依据与使用范围

这份规则适用于目标检测论文的“总体检测准确率与推理速度”整理，不适合直接拿来分析图像分类、分割、姿态估计或所有 CV 任务。

## 已配置的内容

配置位置：`backend/configs/domain-pack-cv-detection.yaml`，标识仍为 `cv_detection`，显示名称为“目标检测：准确率与推理速度”。保留既有指标 ID，避免把旧工作区变成另一个领域。

| 项目 | 当前约定 |
|---|---|
| 总体准确率 | VOC AP50、COCO 平均 AP、COCO AP75、COCO 小目标 AP 分开存储 |
| 测试范围 | VOC 2007、2010、2012 和不同 COCO split 分开 |
| 推理速度 | 分开存 FPS 与单张延迟；不自动互取倒数 |
| 时间口径 | 端到端、排除候选框生成的检测器时间、未知，必须区分 |
| 训练条件 | 保留训练集、模型变体、backbone、分辨率、硬件、batch 等条件；未报告时填 unknown |
| 排除项 | 他人对比方法、逐类别 AP、训练时间、相对加速倍数、百分点提升、全测试集总耗时、理论召回率及融合模型 |
| 单位 | % 与 percent 同义；百分点提升不是绝对准确率单位；秒到毫秒按 1000 显式换算并保留原值 |
| 数值检查 | 准确率限于 0～100；指标必须能在被引用的原文中找到原始数值 |
| 证据 | 保留来源片段、页码及表格说明；数值存在不等于列名、行名一定理解正确，仍需复核 |

新增的规则说明、数值范围、换算与缺失字段标记是可选配置；现有其他领域不必补齐这些字段才能继续使用。

最终规则还会检查论文完整方法与条目方法是否一致，排除基线角色和多检测器融合；不会把单网络内部的特征融合一概当成多模型集成。每批最多14000字符，模型输出达到长度上限时整批标为未完成。

本轮真实样本均以VOC结果为主，COCO指标目前只验证了定义与程序约束，没有以真实COCO结果验证抽取质量。分类词表偏向这些历史检测方法，现代Transformer或其他新范式需要扩展词表并用新论文独立检查，不能声称已经覆盖整个CV领域。

## 推荐使用方式

1. 开始一个明确的研究问题，例如比较同一测试集上的目标检测准确率与速度。
2. 先选择少量代表性论文检查提取结果，再批量导入。
3. 别把不同数据集、训练集、硬件、分辨率或时间范围的数值排成无条件排行榜。
4. 修改规则会使尚未提交的旧预览需要重新生成；已经入库的旧结果不会自动被重新提取。
5. 当前矩阵每篇论文 / 指标只显示一个单元格，不能完整表达同文多变体、多训练集结果。正式比较以逐条核验清单与实验条件为准。

本次选择已有本地 v1 的 Fast R-CNN、Faster R-CNN、YOLO；不把后续版本的数值补入旧论文。规则设置与模型提示先冻结，再执行真实接口试提取。预先冻结的 27 条参考记录用于检查代表性结果覆盖，不是对论文所有实验的穷举，更不是两名独立人工评审建立的金标准。

验证结论与逐条判别见本目录的 `REPORT.md`；原始模型结果与修订建议分开保存。所有“支持 / 需修正”等结论为 AI 辅助原文复核，尚需研究者最终确认。
